Custom Unix Wrapper for BI Publisher

A set of reusable Unix shell scripts that trigger Oracle BI Publisher's SOAP web service programmatically — letting database jobs, OIC flows, and scheduled tasks generate formatted reports without embedding SOAP logic in every caller.

Unix ShellSOAP APIBI PublisherOCI LinuxSQL*Loader

The wrapper accepted report path, output format, and parameters as command-line arguments, building the SOAP payload dynamically via heredoc templating. Authentication used Oracle Fusion's token-based security model, with credentials kept in encrypted files rather than hardcoded. It handled the full request lifecycle — submission, status polling, output retrieval — with retry logic for transient failures and timeout handling for long-running reports. Output could be written to the filesystem, loaded into Oracle ATP via SQL*Loader for archival, or emailed to distribution lists. Every stage was logged — timestamps, parameters, duration, response codes, output paths — for the operations monitoring tooling. Integrated as the final step of the period-close pipeline, it triggered report generation automatically once Fusion processing completed, so finance stakeholders had formatted reports within minutes of the data being ready. Report paths, parameters, and delivery targets lived in external config, so new reports could be onboarded without touching the script logic.

OIC Integration Architecture

Oracle Integration Cloud as the backbone connecting VBCS front ends, Oracle Fusion ERP, external data sources, and downstream reporting — spanning real-time, batch, and event-driven integration patterns.

OICREST APIsOracle FusionATPXPath / JS

Real-time REST integrations fed VBCS apps with live Fusion data — worker records from HCM, PO status from Procurement, account data from Finance — with payloads shaped to each caller to minimize overhead. Scheduled batch flows extracted, transformed, and loaded high-volume transactional data into Oracle ATP, with failed records captured to a dedicated error table and surfaced on monitoring dashboards. Event-driven integrations subscribed to Oracle Fusion Business Events — PO approval, JE posting, HCM position change — to trigger notifications, update PaaS data stores, or kick off BI Publisher report bursts. Every integration carried structured logging with business identifiers (PO number, employee ID, JE batch reference) for end-to-end traceability, governed by a shared connection library and a documented integration inventory so new team members could onboard without relying on tribal knowledge.

Enterprise BI Publisher Reporting Suite

A reporting layer that replaced manual extracts and spreadsheet consolidations with formatted, scheduled, and on-demand Oracle Fusion reports for Finance, Procurement, and HR.

BI PublisherOracle FusionPL/SQLRTF Templates

Reports were built on Oracle's delivered data models where possible, and on custom SQL/PL-SQL data sets where standard models didn't surface the needed fields. RTF and XLS templates supported enterprise formatting — conditional formatting, grouping, multi-level summaries — output as PDF, Excel, or HTML depending on use. Coverage spanned journal entry listings, account balance summaries, and intercompany reconciliations in Finance; PO status, requisition aging, and supplier spend in Procurement; headcount and position vacancy reports in HR. Reports ran on Oracle Fusion's scheduler at daily, weekly, or period-end cadence, distributed by email or through the BI Catalog, with burst scheduling delivering personalized slices to each cost-centre owner. Templates and data models were version-controlled under a consistent naming convention, with regular query tuning and bind variables to keep high-volume reports fast.
